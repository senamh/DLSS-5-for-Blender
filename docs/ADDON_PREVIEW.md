# Addon 0.1.9: current viewport, file-only render and working fallbacks

Additional-window creation and destination selectors have been removed. Existing
saved NEW/BOTH values are ignored. Render with Effect always saves a file using
the folder/name/format dialog and does not automatically show a processed frame.
Manual Show Result and optional standard-F12 postprocessing retain current-area
display. There are no addon-created windows.

Fallbacks in 3D View: Ctrl+Alt+D toggles preview, Ctrl+Alt+R opens the file-render
dialog, Ctrl+Alt+Esc stops NR/preview (not a running Blender render; use Esc).
F5-F10 are not addon bindings. F5/F8 help is now conditional on legacy ReShade.
Bindings are owned and removed on disable/owner transfer; Blender's F12/N/Esc
are not replaced. Real simulated key events in Blender verified all three new
bindings and found no conflicts in the factory Window/Screen/3D View/Object maps.
Personal custom keymaps may differ.

Viewport now reuses private, verified runtime copies until preview stops, while
every frame receives a new input directory and fresh logs/evidence. Changed cached
binaries are rejected. Redundant before/after diagnostic PNGs are omitted only in
preview, without weakening the NR evidence gate. For style-only changes, quiet
time is 0.4 s instead of 1.5 s; scene/view settling time and 1280-edge cap stay intact.
Final render resolution, samples and color settings are unchanged.

Measured on the same official Cozy Kitchen payload (1008x950, RTX 5070), including
full diagnostics for a like-for-like comparison: repeat job 5.49 -> 4.12 s,
preparation 1.14 -> 0.04 s. This excludes Cycles convergence, viewport capture and
debounce; it is not a realtime FPS claim. Each run confirmed native feature 18.

Validation: 54 unit tests; actual Cozy Kitchen VIEW_3D NR, style/object refresh,
file-only render with shared settings, no additional window despite stored NEW/
BOTH values; keyboard event routing, registration ownership and style persistence.

## Historical 0.1.8 behavior (destination/window options superseded above)

Use ordinary stock Blender, not the old ReShade-injected preview executable.
The updated desktop launcher starts Steam Blender with the installed extension.
The old runtime remains the isolated worker dependency; no native DLL was replaced.

Choose This / Separate viewport, then Effect in Viewport. The output is drawn
directly in a VIEW_3D area belonging to the same process, project and scene.
The worker uses the same FrameJob and six scene-saved NR controls as final render.
Camera/view, object edits and style changes invalidate the old snapshot; after a
1.5-second quiet interval a new native NR job runs. Stale results are not published.
No comparison image is generated by the normal workflow. Final frame display is
explicitly labelled static; Return to Scene removes it without changing objects.

Render with Effect opens a real dialog with Viewport / File / Both, folder/prefix,
Blender file format, channels, depth and compression/quality. The normal Blender
camera, resolution percentage, samples and compositor remain in use. File settings
and NR parameters are captured at render start. PNG/JPEG/TIFF/BMP/Targa/WebP are
encoded with Blender settings without applying AgX/exposure twice. Existing files
are rejected, never silently overwritten. 16-bit PNG/TIFF containers are supported
but NR precision is still 8-bit SDR. HDR/EXR, multiview and animation are rejected.

This is real feature-18 NR execution in an experimental image-only consumer. It is
NOT an official native Cycles DLSS integration or a game-rate temporal pipeline.
Clean GPUOffScreen.draw_view3d did not supply the actual Cycles image in our probe.
Consequently preview captures the actual rendered editor, crops to the visible
WINDOW region, suppresses its own output/overlays, and processes that snapshot.
Capture can briefly expose the original. UI layout and engine/color-management
differences mean viewport and camera render are not pixel-identical inputs even
though their NR parameters and consumer are shared. Neutral depth/motion and reset
history remain explicit limitations, not claimed real Cycles guides.
New untouched scenes and the Baseline preset use Default, intensity/tone/structure
1, skin -1, automask off, matching the official-demo test and the upstream visual
enhancer's mask default. Explicit saved user settings are not force-migrated.

Validation on stock Steam Blender 5.2.1 / RTX 5070: same/additional VIEW_3D output,
real native NR, parameter refresh, refresh after moving the cube, one reused output
viewport, folder export, full processed frame rather than comparison, return to
scene, alpha/no-double-color-transform, 8/16-bit export, no-overwrite, registration
ownership and saved-style/load handler persistence. Manual Windows UI inspection
confirmed the rendered overlay, addon panel, render destination dialog, directory
picker and successful return from directory selection to the render dialog.

Official-demo evidence: Cozy Kitchen (Nicole Morena, CC-BY-SA), and Panthera Spelaea
(Joanna Kobierska; full credits in the source .blend, CC-BY), from
https://www.blender.org/download/demo-files/ . The unchanged downloaded originals
were rendered with scripts disabled, at a maximum 1024 pixels and 32 Cycles samples
on OptiX for this test. Default and Natural used identical input hashes, intensity,
tone and structure 1, skin -1, automask off. Mean RGB differences /255 were 6.82 /

Do not describe these tests as game-rate, temporal or HDR validation.

## Historical 0.1.7 behavior (superseded)

The main panel now contains intensity and Render + DLSS. Apply to Finished Render
appears only when Render Result contains data; it reprocesses the original with
the current settings without rerendering or accumulating previous DLSS output.
After successful processing, a same-project image window opens automatically:
the entire original frame on the left, the entire processed frame on the right.

frame, never the comparison. Stop appears only during pending/active processing.
Presets, manual controls, the F12 checkbox, additional viewport, screen ReShade
controls and keyboard help live under the collapsed Additional section.
Unused legacy bridge/debug settings are no longer drawn in addon preferences.

These controls process the final image, not the live viewport of ordinary Steam
Blender. Live ReShade still requires the separate Preview launcher and has separate
settings. This is experimental image-only NR with neutral depth/motion placeholders,
not a full Cycles DLSS integration. Output remains single-frame SDR PNG, 96–4096
pixels per axis. A successful NR call does not establish a quality improvement or
guarantee a conspicuous effect. The panel reports actual mean RGB difference /255.
No artificial grading, sharpening or difference amplification is applied.

Validated in stock Steam Blender 5.2.1 with the local RTX 5070 runtime: 48 unit
tests; real registration/ownership and saved-style checks; real render, alpha,

## Keyboard audit (0.1.6)

F10 was still a real ReShade technique binding in 0.1.5: the button simulated that
same key. The preview's F10 toggle, F7 reload and F6 screenshot assignments are now
removed from the active preset/configuration. Buttons use named `TOGGLE`, `RELOAD`,
`SCREENSHOT` and `OVERLAY` actions. The existing window-message bridge internally
uses F24/F23/F22 and F8; it is not a direct ReShade GPU API, and these internal
keys can still be sent by a keyboard with those keys. No Blender-wide keymaps were
changed. The updated startup script and the INI/preset migration must be deployed
together, followed by a Blender restart.

F8 remains the necessary overlay-close fallback when ReShade captures the mouse.
The supplied native DLL has its own F5 NR-pair capture (and a `Capture Screenshot
(F5)` overlay control). That binary was not patched. Blender F12, N and Esc are
also untouched; their button/menu alternatives are described in the addon help.
The installed READ-ME.txt and README-preview.txt no longer instruct users to press
F10/F7/F6 or incorrectly state that the addon cannot process a final render.

The real-window regression sends old F10/F7/F6 keys to the test window and checks
that they do not toggle the technique, recompile effects or save screenshots. It
then verifies that the corresponding named buttons still perform those actions.

## Rendering and menu behavior introduced in 0.1.5

## Current workflow

The sole main interface is **3D View > sidebar > DLSS 5**. The duplicated Render
Properties panel and legacy DLSS Dev panel are no longer registered. Registering
the extension alongside the launcher's bundled package transfers ownership instead
of adding a second menu or a second set of render handlers. Repeated registration
is idempotent; disabling the previous owner does not remove the new owner's UI.

**Рендер + DLSS**, or F12 with **Применять DLSS после F12** enabled, renders normally
and processes the completed Render Result. Style, intensity, local tone, local
structure, skin structure and automatic mask are snapshotted at render start and
written to the isolated host's `[RenoDX.DLSS5]` configuration. Later slider changes
do not mutate an in-flight job. The original Render Result and configured Blender
output file are not overwritten. The verified output is packed as **DLSS Render**.
Use **Показать DLSS Render** and **Сохранить DLSS PNG**. Save opens Blender's file
selector and refuses to overwrite an existing file; choose another filename.
**Остановить обработку DLSS** stops the neural worker/pending postprocess, not
Blender's underlying render. Cancelling the render does not launch postprocessing.

The input is the completed, display-transformed Blender image, including the
compositor result. Camera/samples/resolution/compositor settings are not overridden.
Only image-export settings are temporarily changed for an RGBA8 PNG snapshot and
restored in `finally`. Output alpha is restored from that snapshot. No sharpening
or second view transform is applied. Each result includes a JSON report with all
native settings, input/output hashes and explicit Feature 18 execution evidence.

**Limitations:** this is image postprocessing, not a fully guided Cycles denoiser.
It supplies constant far depth, zero motion and reset history, explicitly labelled
as placeholders, not real Cycles guides. Supported output: one SDR sRGB PNG frame,
96..4096 pixels per side. Animation, multiview, HDR/EXR output and perceptual quality
improvement are not verified/supported by this route. Scene presets affect final
processing; the screen ReShade effect still has separate live settings. F12 produces
the DLSS result in interactive Blender after render completion; batch CLI needs its
own event-loop integration. **Новый 3D Viewport** continues to share this project,
scene, objects and frame without saving or spawning another Blender.

## Historical 0.1.4 behavior

**Current behavior:** `Новый 3D Viewport` duplicates a VIEW_3D area through
`bpy.ops.screen.area_dupli('INVOKE_DEFAULT')` in the current Blender process.
The new window shares the existing scene, view layer, objects and frame. It does
not save a snapshot, open a .blend, start another Blender or change the project path.
The command works from the sidebar and Render Properties (which finds an existing
viewport of the same scene). If none exists, it reports an error without changing
the current editor. Camera/view orientation and shading are copied from the source
viewport; the source area is not reconfigured.

Opening another viewport does not inject DLSS into ordinary Blender and does not
reinitialize an already-loaded neural consumer. With this change, the former
`Применить стиль (новое окно)` process-relaunch route is removed. Scene style
sliders still save parameters, but **automatic delivery to the active runtime is
not implemented**. The UI explicitly says this and links to the existing ReShade
controls for live native adjustment. There is no claim of per-viewport isolation
of ReShade settings or confirmation of NR processing in every new swapchain.
The upstream key bridge now targets the foreground window if it belongs to this
Blender process, instead of always sending commands to the first window.

Validation on 2026-09-09: 42 unit tests passed. A real GUI test opened two additional
viewports (from VIEW_3D and PROPERTIES); checked scene/object pointer identity,
shared object edits and frame changes, unchanged file path, and no extra scene or
object datablocks. Process spawning and temporary scene directory creation were
forbidden in the operator test. Report: `%TEMP%/dlss5-same-project-test-jf9y8vjt/result.json`.
The test used the preview's standard 1280x720 startup geometry; an initial attempt
without this geometry exited before reaching the script. No user project was opened.
This is a window/data-sharing test, not an NR image-quality or multi-window GPU test.

## Historical styles (0.1.3)

The DLSS 5 sidebar and Render Properties now expose **Мягкий**, **Сброс / базовый**,
**Кино-тон**, and **Выразительный** preset buttons, plus editable model style,
intensity, local tone, local structure, skin structure and automatic mask.
These are project starting points, NOT calibrated quality modes or settings copied
from the user's YouTube references. `Кино-тон` adjusts tone/structure using native
style Default; it is not the native Cinematic model. Style Natural is experimental.
Native Cinematic (2) is excluded because the upstream Feeder documents a startup
crash on a reference runtime; this does not establish that every runtime crashes.
Intensity is a model parameter, not a linear original/effect blend.

Settings belong to each Blender scene and are saved in `.blend`. Changing a preset
or slider does **not** change an already-running native consumer. Click **Применить
стиль (новое окно)**, or **Открыть сцену с DLSS** outside preview. The operator saves
a scene copy and generates a separate ReShade.ini and shader preset in the session
directory. `RESHADE_BASE_PATH_OVERRIDE` selects it before process startup. Shader
and addon paths are remapped to the installation; the installed INI is not edited.
Screenshots go to the new session's `Screenshots` folder. External screenshot
commands are cleared in the copy. Unsupported ReShade builds and an INSTALL
BasePath override fail explicitly rather than silently ignoring the chosen style.

The supplied `scripts/deploy_preview_addon.py` can update Python UI files in the
existing desktop preview, keeping a backup. It does not rebuild or replace Blender,
NVIDIA libraries, Feeder or RenoDX. The existing Desktop CMD launcher then loads
the same addon panel on its next launch.

## Preview launch and button controls

Installing the extension alone does not inject DLSS into the current Blender
process. The extension now makes this explicit and provides **Open Scene in
DLSS Preview** in the 3D View sidebar, **N > DLSS 5**, and in Render Properties.

The command finds the existing RTX 5070 preview installation (or the executable
chosen in addon preferences), saves a temporary copy of the current scene, then
opens it in a separate OpenGL Blender window with the upstream preview controls.
The original scene path remains unchanged. Scene scripts and saved window layouts
are not loaded in that window. Existing external assets still need to be accessible.

In the preview window the **DLSS 5** panel has buttons for toggling DLSS,
reloading after resizing, opening/closing ReShade settings, taking an effect
screenshot and starting an ordinary Blender render. Keyboard input is optional;
expand **Показать резервные клавиши** for the fallback bindings. If the ReShade
overlay captures the mouse and blocks the addon panel, **F8** closes it.
The buttons send the existing upstream bindings internally; they do not infer or
display a potentially incorrect on/off state. The initial reload is delayed six seconds.
This processes the displayed application frame, including UI. F12 files are not
processed by this route. Native bridge and payload developer commands are in
Advanced; the earlier ZIP only exposed these unfinished paths.

Local test on 2026-09-09: the actual launch operator saved a copy, retained the
original file path and opened a Cycles scene. The preview process loaded Feeder,
RenoDX and NVIDIA DLLs. Its ReShade.log1 confirmed Feature 18 evaluations at
1280x720 (counts 1 and 60). The window was visually inspected. The simple cube
scene does not establish perceptual improvement, final render integration, or
correct temporal guides. Log suffixes vary when multiple Blender processes run.

Temporary scene copies and session logs remain in `dlss5-preview-scene-*` folders
under the Windows temporary directory, so an unexpected child exit can be diagnosed.
